# Deutsch Live Classroom

Полноценный **teacher-gated voice service** для синхронных уроков немецкого в Zoom или отдельно в браузере.

Ученик говорит на своём клиенте → ElevenLabs Scribe передаёт промежуточный и финальный транскрипт → AITUNNEL заранее создаёт пакет адаптированных реакций → преподаватель выбирает/редактирует фразу экранными фишками → ElevenLabs озвучивает её непосредственно в браузере ученика.

## Что реализовано

- мгновенная синхронизация преподавателя и ученика через Socket.IO/WebSocket;
- отдельные страницы `/teacher` и `/student`;
- teacher approval gate: модель никогда не говорит без кнопки преподавателя;
- экранные фишки: спросить, ответить, recast, продолжить, уточнить, проще, короче, Ja/Nein, A/B, начало, полный образец, без новых слов;
- видимая лестница scaffolding 0–6;
- ручной ввод реплики ученика и свободной инструкции модели;
- ElevenLabs Scribe v2 Realtime с VAD и keyterms текущего урока;
- ElevenLabs Flash TTS, кэширование и предварительная подготовка вероятных ответов;
- кнопки ученика: повторить, медленнее, ключевое слово, начало ответа, полный транскрипт;
- профиль ученика: знает / учит / не знает, известная грамматика, прошлые темы для повторения, цели, ограничения, заметки и прогресс;
- 16 модулей курса и словарные фишки со страниц Wörterliste загруженного Übungsbuch;
- самостоятельный тренажёр `/practice`: отдельные программы A1 и A2 по 16 модулей, 64 ролевых сценария, видимые Wörterlisten и локальная статистика прогресса;
- журнал действий и итог урока;
- REST API и Swagger UI `/api-docs`;
- JSON-хранилище с атомарной записью; поддерживает Render Persistent Disk;
- демонстрационный fallback без внешних API.

## Модель AITUNNEL

На момент сборки в документации AITUNNEL есть модели:

- `gpt-5.4-mini` — дефолт для минимальной задержки;
- `gpt-5.5` — более качественный, но более тяжёлый вариант.

Отдельного идентификатора `gpt-5.5-mini` в опубликованном списке нет. Модель выбирается переменной `AITUNNEL_MODEL`, поэтому при появлении такого ID достаточно поменять значение без изменения кода.

## Локальный запуск

```bash
cp .env.example .env
npm ci
npm run build
npm start
```

Открыть:

- `http://localhost:3000/teacher`
- `http://localhost:3000/student`
- `http://localhost:3000/api-docs`
- `http://localhost:3000/health`

Дефолтный пароль в development, если `.env` не заполнен: `teacher`. На публичном сервере обязательно задайте собственные `ADMIN_PASSWORD` и `SESSION_SECRET`.

## Переменные окружения

```dotenv
ADMIN_PASSWORD=сложный-пароль-преподавателя
SESSION_SECRET=длинная-случайная-строка-не-менее-32-символов
PUBLIC_URL=https://your-service.onrender.com
DATA_DIR=/var/data

AITUNNEL_API_KEY=...
AITUNNEL_BASE_URL=https://api.aitunnel.ru/v1
AITUNNEL_MODEL=gpt-5.4-mini
AITUNNEL_REASONING_EFFORT=none

ELEVENLABS_API_KEY=...
ELEVENLABS_VOICE_ID=...
ELEVENLABS_VOICE_LABEL=Голос 1
ELEVENLABS_VOICE_ID_2=...
ELEVENLABS_VOICE_LABEL_2=Голос 2
ELEVENLABS_TTS_MODEL=eleven_flash_v2_5
ELEVENLABS_TIMEOUT_MS=15000
```

В кабинете преподавателя две кнопки озвучивания — по одной на голос.
`ELEVENLABS_VOICE_ID` даёт первую кнопку, `ELEVENLABS_VOICE_ID_2` — вторую;
подписи берутся из `ELEVENLABS_VOICE_LABEL` и `ELEVENLABS_VOICE_LABEL_2`
(по умолчанию «Голос 1» и «Голос 2»). Если второй ID не задан, вторая кнопка
остаётся неактивной и подсказывает, какую переменную добавить. «🐢 Медленнее»
повторяет фразу тем голосом, который был выбран последним.

`ELEVENLABS_API_KEY` остаётся только на сервере. Клиент ученика получает короткоживущий одноразовый Scribe token.

## Проверка

При запущенном сервере:

```bash
npm run smoke
```

Smoke test проверяет health, вход, 16 модулей, создание профиля/комнаты и генерацию адаптированной реакции.

```bash
npm run audio-test
```

Audio test поднимает собственный сервер с подменённым ElevenLabs (ключи и сеть не
нужны) и проверяет весь путь озвучки: рабочую выдачу аудио, Range-запрос Safari,
устаревшую ссылку, отказ ElevenLabs и зависший запрос. Последние два случая
должны приводить к переключению на голос браузера, а не к тишине у ученика.

## Если у ученика нет звука

Браузеры не дают странице включить звук, пока пользователь сам с ней не
повзаимодействовал. В консоли это выглядит так:

```text
play() failed because the user didn't interact with the document first.
https://goo.gl/xX8pDD
```

По персональной ссылке (`/student?room=...&token=...`) ученик попадает в урок
без единого клика, поэтому первая реплика преподавателя приходит раньше любого
касания экрана — и браузер её глушит. Страница ученика и тренажёр справляются с
этим сами:

- звук открывается на первом же касании страницы (кнопка, поле ввода, клавиша);
- если реплика всё-таки пришла раньше, она **не теряется**: появляется кнопка
  «🔊 Включить звук», и по нажатию фраза проигрывается сразу;
- кнопки «Повторить» и «Медленнее» запускают воспроизведение прямо из клика,
  поэтому работают даже до разблокировки;
- на iOS/Safari используется один и тот же элемент `<audio>`: он «открывается»
  внутри жеста и дальше играет все реплики без новых нажатий.

### Если ElevenLabs отвалился

Отдельный случай — звук разрешён, но озвучка всё равно не играет: закончилась
квота ElevenLabs, протух ключ, сервис отвечает 429 или молчит. Раньше ученик
видел «Браузер не смог проиграть это аудио», хотя браузер был совершенно ни при
чём, а преподаватель получал «Отправлено ученику» как будто всё хорошо.

Теперь фраза озвучивается **до** отправки ученику, поэтому отказ ElevenLabs
ловится на сервере:

- ученику уходит `mode: browser`, и реплику читает голос браузера — урок
  продолжается;
- преподаватель видит предупреждение с причиной («закончились символы»,
  «отклонён ключ», «не ответил за 15 с»);
- если и голос браузера недоступен, ученику автоматически раскрывается
  транскрипт, а не пустая карточка;
- `GET /health` показывает последнюю ошибку в поле `ttsLastError`.

Что проверить, если звука по-прежнему нет:

- `GET /health` — поля `elevenlabsTts` и `stt` должны быть `true`; при `false`
  не заданы `ELEVENLABS_API_KEY` / `ELEVENLABS_VOICE_ID` / `AITUNNEL_API_KEY`,
  и вместо ElevenLabs включается голос браузера;
- `GET /health` → `ttsLastError` — почему именно ElevenLabs отказал в последний раз;
- сайт открыт по HTTPS — иначе браузер не даст доступ к микрофону;
- вкладка не отключена (иконка динамика в заголовке вкладки).

## Архитектура

```text
Student browser
  ├─ microphone → ElevenLabs Scribe Realtime
  ├─ typed fallback
  └─ receives approved speech
             ↕ Socket.IO
Node/Express service
  ├─ session/profile store
  ├─ AITUNNEL chat/completions
  ├─ teacher approval gate
  ├─ ElevenLabs TTS + cache
  └─ REST/OpenAPI
             ↕ Socket.IO
Teacher browser
  ├─ live transcript
  ├─ candidate package
  ├─ visual chips/scaffolding
  └─ approve → speak
```

## Важные ограничения

- Для стабильного занятия ученику лучше использовать наушники, чтобы голос агента не возвращался в микрофон.
- Бесплатная файловая система Render сбрасывается при redeploy/restart. Для сохранения профилей и журналов подключите Persistent Disk и задайте `DATA_DIR=/var/data`.
- Один экземпляр сервиса работает сразу. Для горизонтального масштабирования Socket.IO потребуется общий adapter (например Redis), а JSON-хранилище следует заменить БД.

## Версия 1.1 — микрофон преподавателя и контроль входящего звука

На обеих страницах теперь есть:

- выпадающий список доступных устройств `audioinput`;
- сохранение выбранного микрофона в браузере;
- автоматическое переключение активного Scribe-сеанса при смене устройства;
- индикатор уровня входящего сигнала в процентах;
- живая полоска, которая явно показывает, поступает ли звук;
- автоматическое обновление списка при подключении или отключении гарнитуры.

В кабинете преподавателя появился отдельный блок **«Ваш голос → голос носителя»**:

1. преподаватель выбирает микрофон;
2. произносит немецкую команду;
3. Scribe показывает промежуточный текст в момент речи;
4. финальная фраза попадает в редактируемое поле;
5. сервер заранее прогревает ElevenLabs TTS;
6. кнопка **«Выдать ученику вашу команду голосом носителя»** отправляет аудио в клиент ученика;
7. ученик сначала слышит фразу, а транскрипт открывает только собственной кнопкой.

Для доступа к микрофону браузеру нужен HTTPS или `localhost`. Render выдаёт HTTPS автоматически. Названия устройств иногда появляются только после первого разрешения доступа к микрофону — после разрешения список обновляется автоматически.

При одновременной работе с Zoom лучше использовать гарнитуру. Если команда не должна быть услышана дважды — сначала живым голосом в Zoom, затем голосом ElevenLabs — на время диктовки команды следует выключить микрофон в Zoom либо использовать отдельное устройство ввода для сервиса.
