# Развёртывание в Render как Web Service

Это **не Blueprint**. Файл `render.yaml` не нужен и в проект не включён.

## 1. Репозиторий

Распакуйте проект, создайте Git-репозиторий и загрузите файлы в GitHub/GitLab.

Не загружайте `.env` и API-ключи.

## 2. Создание сервиса

В Render:

1. **New → Web Service**.
2. Подключите репозиторий.
3. Runtime: **Node**.
4. Branch: нужная ветка.
5. Build Command:

```bash
npm ci && npm run build
```

6. Start Command:

```bash
npm start
```

> **Важно про `package-lock.json`.** Все ссылки `resolved` в lock-файле должны
> указывать на публичный реестр `https://registry.npmjs.org/`. Если lock-файл
> был сгенерирован в закрытой корпоративной среде, в него могут попасть URL на
> внутренний прокси-реестр — тогда `npm ci` на Render зависает навсегда (Render
> не может достучаться до внутреннего хоста) и падает с
> `npm error Exit handler never called!`. Проверить:
>
> ```bash
> grep -o '"resolved": "https://[^/]*' package-lock.json | sort -u
> ```
>
> Должен быть только `registry.npmjs.org`. Если нет — пересоберите lock из среды
> с доступом к публичному npm: `rm -rf node_modules package-lock.json && npm install`.

7. Health Check Path:

```text
/health
```

Render сам передаёт `PORT`; код слушает `0.0.0.0:$PORT`.

## 3. Environment Variables

Обязательные для публичного запуска:

```text
NODE_ENV=production
ADMIN_PASSWORD=<длинный пароль>
SESSION_SECRET=<случайная строка 32+ символа>
PUBLIC_URL=https://<имя-сервиса>.onrender.com
AITUNNEL_API_KEY=<ключ AITUNNEL>
AITUNNEL_BASE_URL=https://api.aitunnel.ru/v1
AITUNNEL_MODEL=gpt-5.4-mini
AITUNNEL_REASONING_EFFORT=none
AITUNNEL_STT_MODEL=whisper-1
ELEVENLABS_API_KEY=<ключ ElevenLabs>
ELEVENLABS_VOICE_ID=<ID немецкого голоса>
ELEVENLABS_TTS_MODEL=eleven_flash_v2_5
```

`gpt-5.5-mini` сейчас не опубликован как отдельный ID в документации AITUNNEL. Для быстрого режима используйте `gpt-5.4-mini`; для максимального качества — `gpt-5.5`.

### Распознавание речи (STT) — AITUNNEL Whisper

Микрофоны преподавателя и ученика распознаются через **AITUNNEL Whisper**
(эндпоинт `POST /v1/audio/transcriptions`, OpenAI-совместимый). Отдельный ключ
не нужен — используется тот же `AITUNNEL_API_KEY`. Браузер записывает короткие
фрагменты речи и по паузе отправляет их на наш сервер, а сервер проксирует их в
AITUNNEL, поэтому ключ не попадает в браузер.

Модель задаётся переменной `AITUNNEL_STT_MODEL` (по умолчанию `whisper-1`).
Доступные варианты у AITUNNEL: `whisper-1`, `whisper-large-v3`,
`whisper-large-v3-turbo`, `gpt-4o-transcribe`. Для лучшего качества по-немецки
можно поставить `whisper-large-v3-turbo`.

Необязательные переменные: `AITUNNEL_STT_LANGUAGE` (по умолчанию `de`),
`AITUNNEL_STT_TIMEOUT_MS` (по умолчанию `30000`), а также
`AITUNNEL_STT_API_KEY` / `AITUNNEL_STT_BASE_URL`, если STT нужно направить на
отдельный ключ или адрес.

ElevenLabs теперь используется **только для озвучивания (TTS)**, распознавание
речи через ElevenLabs Scribe больше не применяется.

## 4. Persistent Disk

Без диска профили и журналы исчезнут после пересоздания экземпляра.

1. В настройках Web Service добавьте Persistent Disk.
2. Mount Path:

```text
/var/data
```

3. Добавьте переменную:

```text
DATA_DIR=/var/data
```

Минимального небольшого диска достаточно для профилей и текстовых логов. Аудио хранится только в оперативном кэше и на диск не записывается.

## 5. Проверка после deploy

Откройте:

```text
https://<service>.onrender.com/health
https://<service>.onrender.com/teacher
https://<service>.onrender.com/student
https://<service>.onrender.com/api-docs
```

В `/health` должны быть:

- `ok: true`;
- `aitunnel: true`;
- `stt: true` (распознавание речи через AITUNNEL Whisper);
- `elevenlabsTts: true`.

## Тренажёр без преподавателя (`/practice`)

Раздел самостоятельной практики: ученик открывает `/practice`, выбирает уровень
A1 или A2, модуль (1–16) и режим, а модель AITUNNEL (`AITUNNEL_MODEL`,
«ChatGPT-mini») ведёт с ним диалог по-немецки. Логин и комната не нужны.
Для обоих уровней доступны словари модулей; A2 загружен со страниц Wörterliste
15, 25, 35, ... 165 соответствующего Übungsbuch.

Два режима:

- **Диалог по теме** — ИИ задаёт вопросы так, чтобы ответ требовал грамматики
  модуля (например, для «Imperativ + Gesundheit»: «Ich habe Kopfschmerzen. Was
  soll ich machen?» — ученик отвечает командами).
- **Ролевые сценарии** — для каждого из 16 модулей каждого уровня есть 2 сценария; ИИ берёт
  роль (продавец, друг, врач, администратор…), ученик отвечает как второй
  участник. Например, модуль 12: «Ленивый друг» и «Совет по здоровью».

ИИ на каждом шаге даёт короткое исправление ошибочных слов в формате
«Nicht … . … .» и подсказку по-русски. Голос (Whisper для ввода и ElevenLabs
для озвучивания) подключается автоматически, если заданы соответствующие ключи;
без них раздел работает в текстовом виде.

Статистика хранится в `localStorage` браузера отдельно для A1 и A2: количество
занятий и ответов, процент ответов без исправлений, лучшая серия и результаты
по каждому модулю. Её можно сбросить кнопкой на странице тренажёра.

## 6. Первый урок

1. Войти на `/teacher` с `ADMIN_PASSWORD`.
2. Создать профиль ученика.
3. Выбрать модуль и отметить слова фишками.
4. Нажать «Создать учебную комнату».
5. Отправить ученику персональную ссылку.
6. Ученик нажимает «Включить микрофон».
7. После реплики ученика выбрать вариант и нажать «Сказать ученику».

## 7. WebSocket

Дополнительный отдельный сервис не нужен: Render Web Service проксирует WebSocket, а Socket.IO использует тот же домен и порт.

## Микрофоны преподавателя и ученика

Дополнительных переменных окружения для выбора микрофона и индикатора уровня не требуется. Выбор устройства выполняется в браузере каждого участника.

Проверьте после деплоя:

1. Откройте `/teacher` и создайте комнату.
2. В блоке «Ваш голос → голос носителя» выберите микрофон и разрешите доступ.
3. Убедитесь, что полоса уровня движется при речи и появляется промежуточный транскрипт.
4. Нажмите «Выдать ученику вашу команду голосом носителя».
5. На `/student` выберите отдельный микрофон, включите его и проверьте собственную полосу уровня.

Render предоставляет HTTPS, поэтому `getUserMedia` работает без дополнительной настройки сертификатов. В браузере доступ к микрофону должен быть разрешён отдельно для домена сервиса.
